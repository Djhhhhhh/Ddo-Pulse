## 1. 项目概述

### 1.1 项目名称
Ddo-Pulse 信息源逻辑重构

### 1.2 一句话定义
将信息源从 pipeline_jobs 中解耦为独立全局实体，支持本地 CSV 文件作为信息源权威来源的全量覆盖同步，并支持 per-source 级别的关注点配置。

### 1.3 设计意图
- **解耦信息源与定时任务**：信息源作为全局资源独立存在，不因删除某个源而影响定时任务的调度执行
- **本地文件驱动**：用户在项目 `docs/` 目录下手动维护信息源表格（CSV），作为信息源的权威来源
- **前端全量覆盖**：提供按钮一键将本地 CSV 文件内容全量同步到系统中
- **Per-source 关注点**：同一个定时任务下，每个信息源可独立配置关注哪些信息（如关键词、分析深度等）

## 2. 术语表（Glossary）

| 术语 | 定义 |
|---|---|
| 信息源（Source） | 一个可被抓取的内容来源，包含名称、类型、URL 等基础信息 |
| 定时任务（Pipeline Job） | 一个按 cron 调度执行的抓取-分析-推送流水线 |
| 信息源表格 | 用户在 `docs/` 目录下手动维护的 CSV 文件，记录所有信息源的基础信息 |
| 全量覆盖 | 前端按钮触发的操作：用 CSV 文件内容完全替换系统中的信息源列表 |
| 关注点配置 | 每个信息源在某个定时任务下的个性化配置，如关注关键词、分析深度等 |

## 3. 功能需求（Functional Requirements）

### 3.1 信息源独立化

- **FR-SRC-1**：信息源（Source）应作为全局实体独立存在，不再强制绑定到某个 pipeline_job
- **FR-SRC-2**：信息源应有唯一标识（如 URL 或名称+类型组合），支持跨定时任务共享
- **FR-SRC-3**：删除一个信息源不应影响任何定时任务的调度和执行

### 3.2 本地 CSV 文件同步

- **FR-CSV-1**：系统应支持从项目 `docs/` 目录下的 CSV 文件读取信息源列表
- **FR-CSV-2**：前端应提供「全量覆盖」按钮，将 CSV 文件中的信息源列表完全替换系统中的信息源
- **FR-CSV-3**：全量覆盖操作应为幂等的——多次执行结果一致
- **FR-CSV-4**：CSV 文件的列定义应包含：类别、源名称、源类型、rss_url、官网链接、内容频率、简介、质量评级等（与现有 `ddo_pulse_rss_seed_library.csv` 格式兼容）

### 3.3 定时任务与信息源关联

- **FR-JOB-1**：定时任务通过关联表引用信息源（多对多关系），而非外键绑定
- **FR-JOB-2**：定时任务可引用零个或多个信息源；信息源可被零个或多个定时任务引用
- **FR-JOB-3**：全量覆盖信息源时，已关联的定时任务应保留其关联关系（按源标识匹配）

### 3.4 Per-Source 关注点配置

- **FR-FCS-1**：同一个定时任务下，每个关联的信息源可独立配置「关注点」
- **FR-FCS-2**：关注点配置应包含但不限于：关注关键词、是否需要 LLM 分析、是否需要网页正文提取、分析深度限制等
- **FR-FCS-3**：关注点配置应存储在关联表中（而非修改信息源本身的基础信息）
- **FR-FCS-4**：前端应在定时任务的源列表中提供 per-source 关注点的编辑入口

## 5. 关键流程

### 5.1 全量覆盖流程

```text
用户编辑 docs/ddo_pulse_rss_seed_library.csv
        │
        ▼
前端点击「全量覆盖信息源」按钮
        │
        ▼
后端读取 CSV 文件
        │
        ▼
对比现有 sources 表：
  - CSV 中有、DB 中无 → 新增
  - CSV 中有、DB 中有（按 URL 匹配）→ 更新基础信息
  - CSV 中无、DB 中有 → 标记为待处理（见开放问题 Q-1）
        │
        ▼
更新 sources 表
        │
        ▼
同步 job_sources 关联表（保留已有关联）
```

### 5.2 定时任务执行流程

```text
APScheduler cron 触发
        │
        ▼
加载 pipeline_job 配置
        │
        ▼
查询 job_sources 表，获取关联的 sources
        │
        ▼
对每个 source：
  1. 读取 per-source 关注点配置
  2. 使用 fetcher 抓取内容
  3. 按关注点配置决定是否 LLM 分析、分析深度等
        │
        ▼
聚合 digest → 推送
```

## 6. 约束与原则

- **C-1**：CSV 文件为信息源的唯一权威来源（single source of truth）
- **C-2**：全量覆盖是破坏性操作，前端应有确认提示
- **C-3**：信息源的基础信息（名称、URL、类型等）来自 CSV；关注点配置不在 CSV 中维护（在前端 per-job 维护）
- **C-4**：已有的 raw_items、analyzed_items 数据在源重新关联后应保持可访问
- **C-5**：向后兼容——现有 pipeline_jobs 的功能不应因本次重构而丢失

---

## 7. 验收标准（Acceptance Criteria）

- **AC-1**：用户可在 `docs/ddo_pulse_rss_seed_library.csv` 中添加/删除/修改信息源，然后在前端点击按钮完成全量覆盖同步
- **AC-2**：删除 CSV 中某个信息源并全量覆盖后，已关联该源的定时任务仍正常执行（不受影响）
- **AC-3**：同一个定时任务下，不同信息源可配置不同的关注关键词和分析参数
- **AC-4**：定时任务执行时，按各 source 的关注点配置进行差异化处理
- **AC-5**：全量覆盖操作是幂等的，重复执行结果一致

---

## 8. 非功能需求（Non-Functional）

- **NFR-1**：全量覆盖操作应在 5 秒内完成（假设 CSV 不超过 500 行）
- **NFR-2**：CSV 文件格式应与现有 `ddo_pulse_rss_seed_library.csv` 兼容，用户无需修改已有文件

---

## 9. 范围说明（In / Out of Scope）

### In Scope
- 信息源从 pipeline_jobs 解耦为全局实体
- CSV 文件全量覆盖同步机制
- Per-source 关注点配置（存储与 UI）
- 定时任务执行逻辑适配新数据模型

### Out of Scope
- CSV 文件的增量同步（仅支持全量覆盖）
- 信息源的自动发现/推荐
- CSV 文件的 Web 在线编辑（用户在本地编辑）
- 信息源的分组/标签管理
