# 用户需求

> 用户触发此流水线的原始需求描述。

## 原始需求

将这些内容作为需求来写一下吧，这个需求需要同步修改后端和前端，后端改分析流程，前端改定时任务支持这种需求的配置。

以下是需求的详细内容（来自用户先前的设计方案）：

### 整体设计思路

目标：每日从约 15~20 个 RSS 源中抓取 ~100 篇新文章，经 LLM 分析后，最终推送 10~15 篇高价值内容，保持 AI 前沿与软件开发的平衡。

### 1. 每日获取哪些源？每源获取多少篇？

按优先级将源分为三组，设置不同的抓取数量（取最新 N 篇）：

| 组别 | 源名称 | 每源抓取数 | 备注 |
|---|---|---|---|
| P0-核心必读（8个） | OpenAI Blog、Google DeepMind、Google AI、Meta AI、Hugging Face、arXiv·AI、arXiv·ML、Simon Willison | 5 篇 | 更新频率低但价值极高 |
| P1-高优（6个） | Microsoft Research、arXiv·NLP、Netflix TechBlog、Cloudflare、美团技术、阮一峰 | 4 篇 | 次重要，频度较高 |
| P2-补充（6个） | Hacker News、GitHub Blog、TechCrunch、V2EX、Martin Fowler、Jeff Geerling | 3 篇 | 社区和综合资讯 |

每日总获取量 = 8×5 + 6×4 + 6×3 = 82 篇

### 2. 分析与排名规则

- 分析对象：所有获取到的文章全部送入 LLM 分析
- 不按源独立推送：所有文章混合后统一排名
- 排名时加入类别权重，避免单一领域霸榜
- LLM 分析输出：3点核心观点、标签、相关性评分(0~10)、新颖度评分(0~10)
- 综合得分 = 相关性×0.6 + 新颖度×0.4（可调）

### 3. 推送比例与排名规则

- 分析总量 ≈ 80~100 篇
- 推送数量：固定 12 篇
- 推送构成：
  - AI 前沿（论文、模型、研究）：6 篇
  - 软件开发（工程实践、架构、工具）：4 篇
  - 综合/跨界（科技趋势、创业、社区热点）：2 篇

### 4. 排名算法

1. 分类过滤：根据 LLM 打标，分出 AI、开发、其他三池
2. 池内排序：每池内按综合得分降序
3. 按比例截取：AI 池前6、开发池前4、其他池前2
4. 最终排序：12篇按综合得分全局降序重排
5. 某池不足时从其他池高分文章补足，保持总推送数不变

## 需求摘要

重构 Ddo-Pulse 内容管线：引入源优先级分组（P0/P1/P2）与每源抓取上限、双维度评分（相关性+新颖度）、类别权重排名、推送类别配额均衡（AI 6 + 开发 4 + 综合 2 = 12 篇），同步修改后端分析流程与前端定时任务配置界面。
