## 2. 整体架构

```
┌───────────────────────────────────────────────────────────────────────┐
│                           screenshot.py                              │
│                                                                      │
│  ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐    │
│  │ slide 截图       │   │ cover 头条封面   │   │ cover 次条封面   │    │
│  │ width=1080      │   │ 900 × 383       │   │ 200 × 200       │    │
│  │ full_page=True  │   │ 2.35:1          │   │ 1:1             │    │
│  └─────────────────┘   └─────────────────┘   └─────────────────┘    │
└───────────────────────────────────────────────────────────────────────┘
```

关键事实：
- 幻灯片截图：宽度 1080px，使用 full_page=True 捕获完整内容
- 头条封面：900×383px，符合公众号头条封面规范（约2.35:1比例）
- 次条封面：200×200px，符合公众号次条封面规范（1:1比例）
- 封面图均从 HTML 首页（第一张幻灯片）裁剪生成

## 3. 微信公众号图片规范

| 类型 | 尺寸 | 比例 | 用途 |
|------|------|------|------|
| **头条封面大图** | 900 × 383 像素 | 约 2.35:1 | 文章列表封面 |
| **次条封面小图** | 200 × 200 像素 | 1:1 | 次条文章封面 |
| **文中图片** | 宽度 1080 像素 | 不限 | 文章内配图 |

**注意事项**：
- 封面大图核心内容应放在中间区域（约500×500安全区）
- 图片格式推荐 JPG/PNG
- 文中图片单张不超过 10MB

## 4. 核心修改

### 4.1 修改点一：幻灯片截图完整捕获

**文件**: `services/backend/tools/publishers/screenshot.py`

**修改内容**:
```python
# 修改前（第 47 行）
page.screenshot(path=str(screenshot_path))

# 修改后
page.screenshot(path=str(screenshot_path), full_page=True)
```

**原理**:
- `full_page=True` 让 Playwright 自动计算页面实际高度
- 捕获整个可滚动区域，而不仅仅是视口内的内容

## 5. 关键算法 / 流程

### 5.1 修改后的截图流程

1. 启动 Chromium 浏览器（headless）
2. **生成封面图**：
   a. 头条封面：viewport 900×383，保存为 `cover-main.png`
   b. 次条封面：viewport 200×200，保存为 `cover-sub.png`
3. **生成幻灯片截图**：
   a. 创建页面，viewport width=1080, height=800
   b. 获取幻灯片总数
   c. 对每个幻灯片：
      - 调用 `show(i)` 显示当前幻灯片
      - 等待 500ms 渲染完成
      - 调用 `page.screenshot(full_page=True)` 截取完整页面
4. 关闭浏览器
5. 返回所有截图路径（包含封面图）

## 6. 错误处理与回退

| 触发条件 | 行为 |
|----------|------|
| Playwright 未安装 | 记录警告，返回空列表 |
| HTML 文件不存在 | 记录警告，返回空列表 |
| 截图过程异常 | 记录异常，返回已成功截图的列表 |
| 封面图生成失败 | 记录警告，继续生成幻灯片截图 |

## 7. 风险与权衡

| # | 风险 | 描述 | 处置 |
|---|------|------|------|
| R-1 | 内存占用 | full_page 可能导致大页面占用更多内存 | 当前报告内容量可控，风险低 |
| R-2 | 截图尺寸 | 完整页面截图文件可能较大 | 可接受，信息完整性优先 |
| R-3 | 封面图裁剪 | 900×383 可能裁剪部分内容 | 设计时确保核心内容在安全区内 |
